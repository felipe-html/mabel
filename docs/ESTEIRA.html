Esteira do Mabel

Do projeto vazio ao PR: o que cada comando faz e devolve, quais agentes rodam em cada etapa, o que cada um entrega e quais gates o código do Mabel aplica entre eles.

agente (run claude -p) passo do Mabel, sem agente gate mecânico decisão humana / needs_human reprova: nova tentativa blocked / failed
1 · Visão geral

A jornada em cinco blocos

Você prepara o backlog, o run consome a fila com três agentes, para quando precisa de você e deixa cada tarefa pronta na branch da sua unidade (spec ou avulso). A mabel/integracao, refeita a cada run, só serve para teste. Só você leva a unidade à base.

2 · mabel run

A esteira de um item

Um item por vez, uma etapa por vez. Cada etapa com agente é uma run claude -p com saída estruturada (--json-schema). Entre elas, o código do Mabel decide se o item avança. Nada é declarado pelo agente: o “done” é calculado.

Toda run é auditada (G1)Modelo, custo, tokens, ferramentas e transcript no SQLite e em ~/.mabel/runs/. Sem registro, a run não inicia.
Contexto hermético (G8)--restricted, --strict-mcp-config, sem slash commands, --tools por etapa. Só prompt do Mabel + CLAUDE.md + regras críticas.
Escopo (G4)Hook PreToolUse nega escrita fora dos globs do plano; sandbox confina o terminal ao worktree; o agente não usa git de escrita.
Teto por run (G6)--max-turns e --max-budget-usd por etapa, e a política de saldo antes de cada uma.
1ª tentativa reprovaA 2ª retoma a mesma sessão do executor com o motivo da reprovação.
2ª reprovaA 3ª abre sessão nova, com o resumo das tentativas, no modelo da camada acima (sonnet → opus).
3ª reprovaneeds_human · attempts_exhausted, com o que reprovou em cada tentativa em português.
Falha da runErro do claude leva a failed. Saldo esgotado no meio: espera o reset e retoma pela mesma sessão.
3 · Agentes

Os cinco agentes

Cada agente é um prompt em prompts/ com um esquema de saída em src/schemas/stages.ts. Só o executor escreve arquivos. Modelos e limites são os padrões do config.json.

Nascer

mabel nascer · prompts/nascer.md
Quando
Projeto novo ou repositório sem .mabel/, antes do init.
Run
sonnet · Read Glob Grep · 40 turnos · US$ 2 · até 3 rodadas na mesma sessão
Recebe
Sua descrição em texto livre e o código existente.
Devolve
entendimento, perguntas (≤ 5 por rodada, com sugestão), suposicoes e proposta: stack, CLAUDE.md, regras críticas, backlog de 3 a 10 itens.
Depois
Você revisa; o Mabel grava pelo caminho do init e commita .mabel/ e CLAUDE.md.

Especificador

mabel especificar · mabel refinar · etapa specify · prompts/especificar.md
Quando
Spec de .mabel/specs/ não entregue (especificar) ou avulso em backlog ou ready que nunca foi planejado (refinar).
Run
sonnet (models.refine) · Read Glob Grep · 30 turnos · US$ 1 por rodada · na raiz do projeto · até 5 rodadas na mesma sessão (--resume)
Recebe
O rascunho da spec (ou o avulso) com as referências da spec, o código, o .mabel/regras.md (com orçamento de 20.000 caracteres; acima, aviso de consolidar) e, por Grep, as entregas anteriores. Nas rodadas seguintes, as respostas e as regras que elas mexem.
Devolve
Example Mapping: historia, regras com exemplos (situação → resultado, borda), perguntas (≤ 5, cada uma de um exemplo sem resultado), decisoes, foraDoEscopo, conceitosCriticos, alteracoesRegrasVigentes, tarefas, sugestaoQuebra, reproducao (bug).
Limites
Exemplo sem resultado e sem pergunta, mais de 5 perguntas, pergunta na última rodada, tarefa citando regra que não existe, alterar nas regras vigentes sem antiga → nova ou com a regra antiga fora do assunto, ou bug sem reprodução: correção pedida na mesma sessão, uma vez.
Depois
Você responde (enter aceita a sugestão, texto responde, p adia) e revisa parte a parte. especificar grava a spec (com as seções próprias e as Referências do rascunho como estavam), as tarefas e o estado aceita; refinar, o bloco do avulso.

Planejador

etapa plan · prompts/planejar.md
Quando
Item em planning, dentro do run.
Run
opus · Read Glob Grep · 40 turnos · US$ 3 · no worktree do item
Recebe
Item (tarefa de spec: história, seções próprias, regras citadas, decisões e fora do escopo da spec), regras críticas, referências congeladas (as do item e as herdadas da spec); num replanejamento, o plano anterior e o resumo das tentativas.
Devolve
plano.json: critérios com verificacao e comportamento, escopo em globs, passos, suposicoes, conceitosCriticos, perguntas.
Depois
Gate de início (G2) → planned ou needs_human.

Executor

etapa execute · prompts/executar.md
Quando
Item em executing; volta aqui a cada reprovação.
Run
sonnet (opus na 3ª) · Read Glob Grep Edit Write Bash · 120 turnos · US$ 8 · hook de escopo, sandbox, sem git commit/push/merge, curl, sudo
Recebe
O plano; na retentativa, o motivo da reprovação ou o resumo.
Devolve
execucao-N.json: testes por critério, suposicoes, perguntas, escopoAdicional, impedimento. E as edições no worktree.
Depois
O Mabel commita e roda a verificação e a prova.

Revisor

etapa review · prompts/revisar.md
Quando
Item em reviewing, depois da prova.
Run
opus · Read Glob Grep, Bash só para git diff, log, show · 40 turnos · US$ 3
Recebe
Plano, execução e o diff da branch contra a base.
Devolve
Parecer: cada critério com atendido e evidencia; problemas bloqueantes e menores.
Depois
O Mabel calcula o veredito e integra, ou devolve ao executor.
4 · Comandos

O que cada comando faz e devolve

Na ordem da jornada. Quase todos aceitam --json, para o mabel-ui, e mabel comandos explica as opções de cada um. As saídas de terminal são exemplos ilustrativos montados a partir dos formatos do código, não capturas reais.

Integrar e entregar da integração para a base

integracaoleitura

mabel integracao

As unidades do relatório de run: prontas para entregar (spec com tarefas concluídas, avulso), em andamento e a integração (base + unidades incluídas, as de fora, a verificação), com o que olhar primeiro.

Grava: .mabel/run.md: precisa de você, prontas para entregar, em andamento, integração (por item: plano, arquivos, prova, devoluções, custo) e as tarefas do run.

entregarvocê pede

mabel entregar [slug | #n] [--com unidade] [--parcial] [--substituir] [--rascunho]

Entrega uma unidade (spec ou avulso). Parcial pede confirmação (TTY) ou --parcial; dependência fora da base recusa, com a sugestão --com. Antes de criar qualquer branch, a prova: base + merge do snapshot da unidade num worktree temporário, e a verificação do projeto; conflito ou vermelho recusam. Depois, o documento de entrega e o PR para a base. O merge é seu; no próximo run as tarefas viram done, a spec vira entregue, e o documento e as regras vigentes ficam na base junto do código.

Grava: branch mabel/entrega/<unidade> = snapshot da branch da unidade + commit mabel: entrega <unidade> só com .mabel/entregas/<data>-<unidade>.md e o .mabel/regras.md com as alterações da unidade (trailer Mabel-Entrega; a base não recebe commit), push no remoto, PR pelo gh; a entrega no SQLite, uma aberta por unidade. Sem gh: o endereço e o arquivo do corpo.

Auditar e avulsos sem efeito na fila

status · saldoleitura

mabel status [--atualizar] · mabel saldo

Barras das janelas de 5 h e 7 dias com reset e ritmo; resumo do quadro do projeto (“Aguardando você”, “Em andamento”); runs recentes; pausa por saldo, se houver.

runsleitura

mabel runs [--limite n] · mabel runs id

Toda run auditada: tipo (plan #3, exec, probe), modelo, turnos, duração, custo. O detalhe traz a linha do tempo das ferramentas e o caminho do transcript.

projetos · projeto · eventosleitura

mabel projetos [--removidos] · projeto nome · projeto remover nome · eventos

Auditoria por projeto: custo por etapa e modelo, gates reprovados, escalonamentos, decisões autônomas, pausas. eventos emite uma linha JSON por evento, para o mabel-ui.

exec · comandos · completionavulso

mabel exec "prompt" [--model] [--max-turns] [--max-budget-usd] · comandos [--json] · completion zsh

exec abre uma conversa no Claude Code, com a mesma auditoria e fora de qualquer item: cada mensagem é uma run que retoma a sessão, até sair ou Ctrl+D. comandos lista cada comando com as opções explicadas (em JSON, para outros programas). completion imprime o autocompletar do zsh.
